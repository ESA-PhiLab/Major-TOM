# Data sources for `majortom.build`

`majortom.build` makes Major TOM samples (one window per grid cell) from public Earth observation archives. This page lists what can be read from where, how to set up access, and what to expect.

## 1. Quick start

```python
import pandas as pd
from majortom import build

cells = build.cells_from_points(pd.DataFrame({"lon": [-111.65], "lat": [40.58]}), d=10)
errors = build.download(cells, "sentinel-2-l2a", "2024-08-01/2024-08-31", archive="planetary-computer")
```

Each sample is written as `chips/<product>/<index>.npz` (one array per band) with a `.json` sidecar: grid cell, window, CRS, the source items, the archive, dates, cloud share and how it was measured, the Sentinel-2 offset, declared scaling, processing baseline, platform, and timing.

**Which archive?**

- No account, fastest for most products: **Planetary Computer** (`planetary-computer`, the default).
- Sentinel-2 L1C, or Collection 1 reprocessed L2A: **Earth Search** (`earth-search`), no account.
- ESA's own archive, as the Core datasets were built from: **CDSE** (`cdse`), S3 keys.
- HLS before 2020: **NASA Earthdata** (`earthdata`), a token.
- Landsat 4–9 and L1, MODIS, Dynamic World, Sentinel-1 GRD, VIIRS, Sentinel-3 OLCI: **Earth Engine** (`earth-engine`), a registered Cloud project.

Asking for dates outside a source's period, or a product an archive does not have, raises an error that names the archives that do.

**Which scene.** `download` tries up to five scenes per sample, in the order of `prefer` (`"clearest"`, `"cloudiest"`, `"nearest"` to the date, `"newest"`), and takes the first whose window meets both `cloud` (accepted cloud share, default `(0, 0.05)`; `None` accepts any) and `max_nodata` (accepted share of missing pixels, default `0.01`). If none does:

| `strict` | `fallback` | Result |
|---|---|---|
| `False` (default) | `"complete"` (default) | the scene with the least missing data, then the cloud share closest to the range |
| `False` | `"clear"` | the scene with the cloud share closest to the range, then the least missing data |
| `True` | either | the sample fails, with the reason |

`platform="terra"` (or a list, e.g. `["landsat-8", "landsat-9"]`) keeps only scenes from those satellites; useful for MODIS, where Terra and Aqua composites share their dates. Each sample records its `platform`.

`"complete"` is the default because clouds can be masked later (each sample records its cloud share and, where the product has one, its mask), while missing pixels cannot be recovered. All these settings are recorded in every sample's `choice`.

## 3. Archives

### Planetary Computer (`planetary-computer`)

- **Holds:** Sentinel-2 L2A, Landsat 4–9 L2, HLS (from 2020), Sentinel-1 RTC, MODIS, ASTER L1T (2000–2006), DEMs, land cover, biomass, water.
- **Access:** free, no account. Links are signed automatically.
- **Notes:** Sentinel-2 values carry +1000 from 2022-01-25 (baseline 04.00) and the archive does not declare it; samples record it as `offset`. Original processing, not reprocessed.
- **Gaps:** its HLS copy is incomplete. Over Scotland in June–August 2024 it held 188 of the 217 HLS L30 tile-days that NASA's LP DAAC has (Earth Engine held all 217). Where complete coverage matters, use `earthdata` or `earth-engine` for HLS.

### Earth Search (`earth-search`)

Element 84's catalogue of the AWS Open Data buckets.

- **Holds:** Sentinel-2 L2A (Collection 1 reprocessing), Sentinel-2 L1C (JPEG 2000), Copernicus DEM.
- **Access:** free, no account; `s3://` links are read unsigned.
- **Notes:** the buckets are in US West: from Europe, 10 m bands take several seconds each. Landsat on AWS is requester-pays (an AWS account billed per GB) and is not supported. JPEG 2000 is decoded in one thread per read; samples still run in parallel.

### Copernicus Data Space Ecosystem (`cdse`)

- **Holds:** Sentinel-2 L2A and L1C (JPEG 2000), Copernicus DEM.
- **Access:** S3 keys (not your CDSE login). Create them at <https://eodata-s3keysmanager.dataspace.copernicus.eu>, then run `python -m majortom.build.credentials cdse`.
- **Limits:** 4 connections per account (4 workers); the catalogue rate-limits quick searches, so searches are spaced 1 s apart.
- **Notes:** CDSE now serves reprocessed versions for 2015–2021 (baseline 05.00) and has reprocessed some 2023 data again (05.10). Landsat appears in its catalogue but is not readable with S3 keys.

### NASA Earthdata (`earthdata`)

- **Holds:** HLS L30 (from 2013) and S30 (from 2015) and OPERA DIST-ALERT from LP DAAC; OPERA DSWx-HLS and DSWx-S1 from PO.DAAC; OPERA RTC-S1 from ASF. Collections are named `PROVIDER/ID`.
- **Access:** a token (not your password). Generate one at <https://urs.earthdata.nasa.gov> (Generate Token; valid 60 days), then run `python -m majortom.build.credentials earthdata`.
- **ASF (OPERA RTC-S1) needs a one-off approval** of its download application for your account; until then its reads are refused (401):
  1. Log in at <https://urs.earthdata.nasa.gov>.
  2. In the same browser, open an ASF file link, for example <https://datapool.asf.alaska.edu/RTC/OPERA-S1/OPERA_L2_RTC-S1_T030-062622-IW1_20240604T175938Z_20240604T203842Z_S1A_30_v1.0_VV.tif> (any Sentinel-1 download on <https://search.asf.alaska.edu> works too).
  3. Authorise **Alaska Satellite Facility Data Access** and accept its licence when asked. When the file starts downloading, approval is done; cancel the download.
  4. The same token then works for ASF; nothing to set up again.
- **Notes:** HLS is identical to Planetary Computer's where both have it, but about 12× slower per sample; use it for 2013–2019. OPERA asset names carry the item id, so bands are matched by the end of the name. ASF redirects reads to a second host that needs the token as well, so the token is sent on through NASA's redirects.

### Google Earth Engine (`earth-engine`)

- **Holds:** Sentinel-2 L2A and L1C (harmonized), Landsat 4–9 L2 and 8–9 L1, HLS, MODIS, ASTER L1T, Dynamic World, Sentinel-1 GRD (terrain-corrected, dB), VIIRS night lights, Sentinel-3 OLCI.
- **Access:** a Cloud project registered for Earth Engine, and either your login (`earthengine authenticate`) or a service-account key file. Run `python -m majortom.build.credentials earth-engine`. Needs `pip install 'majortom[build,gee]'`.
- **Notes:** reads with `computePixels` straight onto the window grid. Harmonized Sentinel-2 has the +1000 offset already removed (`offset: 0`). HLS reflectance is returned as integers ×10 000, as in the other archives. Dynamic World, Sentinel-1 GRD, MODIS and ASTER are resampled onto the cell's grid. Earth Engine's terms of use apply on top of each dataset's licence.

## 4. Credentials

| Archive | Environment (wins) | Saved by the setup command |
|---|---|---|
| CDSE | `CDSE_S3_ACCESS_KEY`, `CDSE_S3_SECRET_KEY` | `[cdse]` in `~/.aws/credentials` |
| Earthdata | `EARTHDATA_TOKEN` | `~/.config/majortom/earthdata-token` |
| Earth Engine | `EE_PROJECT`, `EE_SERVICE_ACCOUNT_KEY` (a path) | `~/.config/majortom/earth-engine.json` (the path, not the key) |

- Keys are read when a read starts and exist only inside that read's GDAL or Earth Engine session: never in `os.environ`, sample sidecars or error messages. The setup command never prints them.
- Files are written owner-only (600). **On shared machines, administrators can still read them**: use revocable, limited credentials (S3 keys, tokens, service accounts), never a main password.
- **Slurm:** set the variables inside the job script. **Colab:** copy them from the Secrets panel, e.g. `os.environ["EARTHDATA_TOKEN"] = userdata.get("EARTHDATA_TOKEN")`.
- The repository's tests fail if a file containing something that looks like a key is committed.

## 5. Same data, different archives

Where two archives hold the same processing of an acquisition, samples are **identical pixel for pixel** once each sample's recorded `offset` is removed:

- Sentinel-2 L2A: Earth Search = CDSE for 2021 (05.00) and 2024 (05.11); all three with Planetary Computer for 2024; Earth Engine = Planetary Computer for 2024.
- Landsat L2 (Landsat 5, 1985; Landsat 9, 2024): Earth Engine = Planetary Computer.
- HLS: Earthdata = Planetary Computer; Earth Engine = Planetary Computer for L30.
- Copernicus DEM: identical from all three archives.

Where processing versions differ (Planetary Computer's originals vs reprocessed Collection 1), values differ by up to a few hundred in stored units. That is the reprocessing, not the builder; every sample records its `processing_baseline`. Evidence: [docs/evidence/s2_sources.csv](evidence/s2_sources.csv), `tests/test_sources.py`.

Tiles of one pass overlap. Tiles that contain the whole window are used first, then the lowest tile code, so archives agree where their footprints do. If archives' footprints differ, they may still pick neighbouring tiles (seen for HLS S30 on Earth Engine), with small differences in the overlap.

## 6. Speed

Measured from a server in Europe; distance to each archive is part of every number. Latest report: [docs/reports/2026-10-22-build-speed.md](reports/2026-10-22-build-speed.md). Every sample records its own `timing` (search, scene choice, each band), so you can measure your own runs.

Rough guide at 16 workers (4 for CDSE): HLS and Copernicus DEM several thousand samples/hour; Sentinel-2 L2A about 1,600 (Planetary Computer), 550 (CDSE), 300 (Earth Search); Sentinel-2 L1C about 500–800; Landsat L2 about 500.

## 7. Troubleshooting

| Message | Cause and fix |
|---|---|
| `PermissionError: CDSE needs S3 keys` (or Earthdata, Earth Engine) | Credentials not set up: run the setup command for that archive. |
| `... refused the S3 keys` / `refused the token` (401, 403) | Keys or token expired or wrong: create new ones and run the setup command again. For OPERA RTC-S1, ASF also needs the one-off approval in section 3 (NASA Earthdata). |
| `429` in an error | The catalogue rate-limited the search: retries wait 1, 2, 4 … s; CDSE searches are spaced automatically. Rerun later. |
| `not recognized as being in a supported file format` | The server sent a web page instead of the file (a login or a refused link). For Earthdata: check the token. |
| `has <product> for (...), not <dates>` | The source has no data for those dates; the message lists archives that do. |
| A sample with high `nodata` | The scene does not cover the window, or the product masks clouds; `prefer`, `cloud` and `max_nodata` control the choice. |
| Slow JPEG 2000 (Sentinel-2 L1C on Earth Search, CDSE) | Expected: JPEG 2000 decodes slowly; use more workers, or COG archives where they exist. |
